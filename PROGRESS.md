## Decisions
- WebSocket + JSON frames, tagged "type"; pane bytes base64. mTLS (rustls) with private CA on hub; node keys ed25519.
- Enrollment: operator clicks "Add device" -> 8-char OTP (A-Z2-9 no I/O) + hub fingerprint shown; 5 min, single use; 3 wrong codes anywhere locks until next begin().
- Browsers/phones: PWA of Rune web build served by ulak-remote; passkeys (WebAuthn) only, registered via OTP. Single operator.
- UI: Rune (github.com/anomalyco/rune, pin a `dev` rev). No iOS yet -> PWA for mobile.
- ask_human: blocks 10 min; on timeout returns pending+question_id; when answered hub sends HubToDaemon::Nudge{agent,text} (text has only question id) typed into tmux; agent calls check_answer; renudge every 2 min, max 3, stops on collect.
- Thresholds default CPU 80, GPU 60, load1 = 1.0 x cores. Agent tokens: random 32B hex, only sha256 stored.
- Client cert 90 days, backdated 1 day; no renewal yet (re-enroll). CA key file ca.key mode 0600.

Decisions:
- Hub contract assumed: WS at `<hub>/ws/daemon` (https->wss), enrollment `POST <hub>/enroll` with EnrollRequest JSON -> 200 + EnrollResponse JSON, other status = rejected. Node id = client cert CN.
- Join trust: TLS to the hub is first accepted without verification, then the user types the fingerprint shown in the hub UI; it must equal the SHA-256 of a certificate in the presented chain (so the hub's TLS chain must include the CA cert) BEFORE the OTP is sent, and the returned ca_cert must hash to it. Afterwards only the pinned CA is trusted.
- Guard: blocklisted comm (case-insensitive, exact, both sides truncated to 15 bytes like /proc comm) -> Busy(Gaming); else GPU > 60, CPU > 80 or load1 > cores -> Busy(Load).
- Hello is re-sent when NodeState or the agent set changes (spawn/kill/vanish); Heartbeat otherwise. Vanished tmux sessions are reported AgentStatus::Exited(None) (exit code unknown).
- Attach = capture-pane polling every 250 ms, each change sent as a full redraw (ESC[H ESC[2J + screen). PaneInput / prompt are pasted via load-buffer + paste-buffer (stdin, no shell); nudge = send-keys -l then Enter, control chars rejected. Agent started as `tmux new-session -d ... -- env K=V.. bin args` (no shell). Env CLAUDE_CONFIG_DIR from profile unless spec env sets it.
Gaps:
- tmux integration test not run on the dev box (tmux not installed); run it once with tmux present.
- Spawn blocks the session loop ~1.8 s (startup delay before typing the prompt), heartbeats slip meanwhile.
- Join HTTP client: no chunked responses, no IPv6 literals; no cert renewal (re-run join). No ctrl-c handling for attached pollers beyond process exit.
- Output channel to the hub is unbounded; pane streaming is polling, not pipe-pane diffs.
- ulakd has a dev-dependency on ulak-remote (Enroller) for the join e2e test.

## 2d: browser access (passkeys, sessions, static web, admin API) -- ulak-remote, all tests + clippy pass
Decisions
- `webauthn-rs` 0.6.2 (`danger-allow-state-serialisation` only to store `Passkey` as JSON in `passkeys.credential`). Ceremony state (challenges) is in memory, 5 min, single use, max 256. Tests use `webauthn-authenticator-rs` `SoftPasskey` (dev-dep).
- Registration OTP is spent at `/auth/register/start` (not finish): Browser-kind only; wrong kind/expired/unknown -> 403, locked -> 429; start is rate limited per IP (shares the /enroll limiter). Operator creates the code via `ULAK_BOOTSTRAP_OTP=browser`, stdin `otp browser`, UI AddDevice{browser}, or `POST /api/devices/otp`.
- One WebAuthn user ("operator"); several passkeys, existing ones are excluded from new registrations. Signature counter saved after login.
- RP id: `ULAK_RP_ID`, origin: `ULAK_ORIGIN`; default = first non-IP SAN (WebAuthn forbids IP rp ids), origin `https://<san>:<bound port>`. Bad config only disables passkeys (503), hub still starts.
- Session = 32B random hex, sha256 stored in `sessions` (expiry `HubConfig::session_ttl_ms`, 7 days); valid only while its passkey is not revoked. Session id for kicking sockets = passkey id (`pk-xxxxxxxx`, a NodeId). `Hub::revoke_passkey` deletes sessions + closes their /ws/ui sockets.
- Auth order on UI surface (`/ws/ui`, `/api/*`): session token (Bearer, then cookie `ulak_session`, then `?token=` on /ws/ui only) else UI client cert. 401 = no credentials, 403 = cert of wrong kind/revoked.
- Static: `ULAK_WEB_DIR`; GET only; path never percent-decoded, `..` `\` NUL segments -> 404; missing extension-less path -> index.html (SPA), missing asset -> 404; `Cache-Control: no-cache`. Security headers on every response: CSP (`default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self'; img-src 'self' data:; connect-src 'self' wss:; frame-ancestors 'none'`), nosniff, no-referrer, X-Frame-Options DENY, HSTS. So index.html must not use inline `<script>`/`<style>`.
- PWA shell in `crates/ulak-remote/web/` (manifest.json, sw.js network-only, icon.svg, README.md). Web build adds index.html, ulak.js, ulak_bg.wasm to the served dir.

Endpoints (JSON; no client cert needed for /auth/*)
- `POST /auth/register/start` `{"otp":"ABCD2345","name":"my phone"}` -> `{"challenge_id":"hex","options":<WebAuthn CreationChallengeResponse, i.e. {"publicKey":{...}}>}`. Feed `options` to `navigator.credentials.create(options)` after base64url-decoding fields (or use the webauthn-rs wasm / `@simplewebauthn`-style helper).
- `POST /auth/register/finish` `{"challenge_id":"hex","credential":<RegisterPublicKeyCredential: {id,rawId,response:{attestationObject,clientDataJSON,transports?},type,extensions?}, base64url strings>}` -> `{"id":"pk-1a2b3c4d","name":"my phone"}`; 400 on any verification failure/replay.
- `POST /auth/login/start` `{}` -> `{"challenge_id","options":<RequestChallengeResponse {"publicKey":{...}}>}`; 403 if no active passkey.
- `POST /auth/login/finish` `{"challenge_id","credential":<PublicKeyCredential: {id,rawId,response:{authenticatorData,clientDataJSON,signature,userHandle?},type,extensions?}>}` -> `{"token":"hex64","expires_ms":123}` + `Set-Cookie: ulak_session=<token>; HttpOnly; Secure; SameSite=Strict; Path=/; Max-Age=<ttl s>`; 401 if verification fails (e.g. wrong origin), 400 for unknown/used challenge.
- Browser opens the UI socket with `new WebSocket("wss://" + location.host + "/ws/ui")` (the cookie is sent automatically; same-origin). Fallback for non-cookie contexts: `/ws/ui?token=<token>`. Same JSON frames as cert UIs (HubToUi / UiToHub). The socket closes when the session's passkey is revoked.
- Admin (session or UI cert): `GET /api/devices` -> `{"devices":[{id,kind,hostname,created_ms,revoked}]}`; `POST /api/devices/otp` `{"kind":"node"|"ui"|"browser"}` -> `{"kind","otp","hub_fingerprint","expires_ms"}` (400 bad kind); `POST /api/devices/{id}/revoke` -> 204 (404 unknown); `GET /api/passkeys` -> `{"passkeys":[{id,name,created_ms,revoked_ms|null}]}`; `POST /api/passkeys/{id}/revoke` -> 204 (404 unknown). stdin admin commands unchanged (+ `otp browser`).

## 2e: hub renewal, logout, revoke cleanup, static ETag (ulak-remote) -- tests, clippy, fmt green
Decisions
- `POST /renew` over mTLS (any active device kind; no cert 401, revoked/unknown 403, bad JSON/key 400, rate limited with /enroll). Allowed only when the presented cert has <= `HubConfig::renew_window_days` (30) left; else 409. Cert lifetime `HubConfig::cert_days` (90). The new cert keeps the same CN/device id (so same kind); the stored public key is replaced; `devices.renewed_ms` set (auto-migrated column; `Device.renewed_ms`).
  - Request: `{"public_key":"-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----\n"}` (PEM SPKI; same key allowed), with the current client cert on the TLS connection.
  - 200 response: `{"cert":"<PEM leaf>","ca_cert":"<PEM CA>"}` (same shape as EnrollResponse). 409: `{"earliest_renewal_ms":<unix ms>}`.
  - Client: renew when `not_after - now <= 30 d`, then reconnect with the new cert (open sockets keep working until closed).
- `POST /auth/logout` (Bearer/cookie): 204, deletes that session, clears the cookie (Max-Age=0), closes only that session's /ws/ui sockets (kick key `s-<hash16>`, other sessions of the passkey stay). 401 without a session.
- `revoke_device` of a Node removes it from the Registry and broadcasts `NodeUpdate` with state Offline (no new proto variant); UIs should drop/grey it. Closes the 2c gap.
- Passkey challenges were already 5 min + bounded; now a `Challenges<T>` type with unit test, also swept by the 10 s expiry loop.
- Static: HEAD, strong `ETag` (sha256/32 hex), `If-None-Match` (list, `W/`, `*`) -> 304, symlinks resolved and refused (404) when they leave the web dir; links inside are fine. Hub README at crates/ulak-remote/README.md.
